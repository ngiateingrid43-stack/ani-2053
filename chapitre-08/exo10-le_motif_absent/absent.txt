L'endroit :
Le motif Commande est absent. Les événements NkEvent encapsulent une action (un clic, une touche), mais ils ne sont ni stockés, ni rejoués, ni défaits. Les callbacks sont exécutés immédiatement par DispatchToCallbacks (NkEvent.h:319).

Deux fichiers montrent l'absence :
- include/NKEvent/NkEvent.h:319 : la classe NkEvent ne contient aucune méthode Undo, Replay, ou Execute différé.
- include/NKEvent/NkWindowEvent.h:290 : NkWindowResizeEvent (par exemple) est une struct de données pure, sans comportement.

Ce qui se répète : chaque événement (clic, touche, redimensionnement) est traité de manière ad-hoc dans le code du callback, sans passer par une abstraction Commande.

Le motif :
Le motif Commande conviendrait. Chaque événement pourrait être encapsulé dans un objet Commande (NkClickCommand, NkKeyCommand) qui contient l'action à exécuter et sait la défaire. Un NkCommandManager pourrait gérer une pile de commandes, permettant undo/redo.

Le coût :
Modifier NkEvent pour qu'il produise des Commande au lieu de structs de données. Modifier tous les callbacks pour passer par un NkCommandManager. Risque de casser la gestion actuelle des événements, qui est simple et directe (DispatchToCallbacks immédiat). Le coût est élevé pour un bénéfice qui n'est pas immédiatement nécessaire dans un jeu ou une interface simple.
