Situations :
1. Le joueur maintient la flèche droite. Pull. La touche est un état continu, lu à chaque image via KeyPressedRepeat. Outil : NkGuiInput::KeyPressedRepeat.
include/NKGui/Core/NkGuiInput.h:200
2. Il appuie sur Échap. Push. C'est un événement ponctuel. Outil : NkKeyPressEvent, dans le callback d'événement.
include/NKEvent/NkKeyboardEvent.h:340
3. On veut la position de la souris. Pull. La position est un état, lu à chaque image via mousePos. Outil : NkGuiInput::mousePos.
include/NKGui/Core/NkGuiInput.h:37
4. Un fichier est déposé sur la fenêtre. Push. Événement ponctuel. Outil : NK_DROP_FILE, événement NkDropFileEvent (déclaré dans NkEvent.h:238).
include/NKEvent/NkEvent.h:238
5. La fenêtre est redimensionnée. Push. Événement ponctuel. Outil : NkWindowResizeEvent.
include/NKEvent/NkWindowEvent.h:290
6. Le joueur double-clique. Push. Événement ponctuel distinct du simple clic. Outil : NkMouseDoubleClickEvent.
include/NKEvent/NkMouseEvent.h:376

Les deux bogues :
- Action qui part trois fois (mauvais push pour un état continu) : si on utilisait un callback push sur NkKeyPressEvent pour la flèche droite, chaque répétition automatique du système (auto-repeat) déclencherait un nouvel événement, et le personnage bougerait par saccades. Le bogue classique est de traiter `keyPressed` au lieu de `KeyPressedRepeat` ou de l'état `keyDown`.
- Mouvement qui s'arrête trop tôt (mauvais pull pour un événement ponctuel) : si on testait `mouseDown` à chaque image pour détecter un clic, un clic très rapide (appui + relâchement entre deux images) serait invisible. Le bogue classique est de ne pas traiter `mouseClicked` (calculé par `NewFrame` à partir de `mouseDown && !mousePrev`).
