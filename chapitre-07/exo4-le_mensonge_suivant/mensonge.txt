Le commentaire :
Dans include/NKCanvas/Renderer/Core/NkDrawable.h, ligne 37, le commentaire de la déclaration anticipée affirme : « class NkRenderTarget;  // NkRenderTarget.h — pas encore livre (etape A.5) ». Le fichier dit donc, noir sur blanc, que NkRenderTarget.h n'est pas encore livré et que la classe n'existe pas encore. Le commentaire d'en-tête du même fichier (lignes 7-8) va pourtant dans l'autre sens : « Toute classe qui peut etre rendue par un NkRenderTarget (NkRenderWindow ou NkRenderTexture) en herite et implemente la methode Draw(target, states) » — il parle de NkRenderTarget comme d'une classe existante, concrète, avec deux implémentations connues.

Le code :
Deux faits du code contredisent la ligne 37. D'abord, le fichier include/NKCanvas/Renderer/Targets/NkRenderTarget.h EST livré dans le kit : on l'a lu en entier, il déclare `class NkRenderTarget` avec ses virtuelles pures (`virtual void Clear(...) = 0;`, `virtual void Display() = 0;`, etc.). Ensuite, include/NKCanvas/Renderer/Targets/NkRenderWindow.h l'inclut explicitement, ligne `#include "NKCanvas/Renderer/Targets/NkRenderTarget.h"`, et déclare `class NkRenderWindow : public NkRenderTarget`. La classe NkRenderTarget est donc non seulement livrée, mais héritée publiquement par une classe concrète du kit.

La preuve :
Depuis le dossier du kit, la commande `Test-Path include\NKCanvas\Renderer\Targets\NkRenderTarget.h` rend `True` : le fichier est présent. La commande `Select-String -Path include\NKCanvas\Renderer\Targets\NkRenderWindow.h -Pattern "NkRenderTarget"` rend au moins deux lignes : le `#include "NKCanvas/Renderer/Targets/NkRenderTarget.h"` et le `class NkRenderWindow : public NkRenderTarget`. Enfin, l'ouverture de NkRenderTarget.h montre la déclaration complète de la classe avec ses méthodes virtuelles pures. Le commentaire « pas encore livre (etape A.5) » est donc faux dans les faits, et il est contredit par le code du kit lui-même, pas par une opinion.

Ce qu'il dit de son auteur :
L'auteur a écrit ce commentaire à un moment où NkRenderTarget.h n'existait effectivement pas encore — l'étape A.5 du plan de migration. Il a posé une déclaration anticipée (`class NkRenderTarget;`) pour pouvoir écrire la signature `Draw(NkRenderTarget&, const NkRenderStates&)` sans inclure un fichier qui n'existait pas. C'était juste à l'époque. Puis NkRenderTarget.h a été livré, NkRenderWindow en a hérité, et le commentaire de la ligne 37 n'a pas été mis à jour : il est resté comme un vestige d'une étape franchie. Ce que cela dit de l'endroit : c'est un commentaire de chantier, écrit pour un lecteur qui savait où en était le plan (A.5), et qui n'a pas été relu quand l'étape a été franchie. Ce n'est pas une faute d'auteur, c'est le sort normal d'un commentaire qui décrit un état transitoire : il ment dès que l'état change, et rien ne le corrige automatiquement — alors que le code, lui, se corrige puisqu'il ne compile plus. C'est exactement la leçon de l'exercice : le code est le seul document à jour, et un commentaire qui annonce une étape est un mensonge dès que l'étape a eu lieu.
